# 评测资产维护

评测执行器位于 `backend/src/main/java/com/zlzcode/codeagent/evaluation/`，案例包位于本目录。两者在同一仓库交付；案例包是执行器读取的正式输入，包含题目、独立验收和参考答案，不要求使用模块测试分支才能运行。应用启动方式见[根 README](../README.md#快速开始)。

## 目录职责

当前案例包为 `case-packs/hmall/`；后续其他仓库的案例包可放在 `case-packs/<name>/`，不需要改变执行器的语言无关边界。

| 案例包内位置 | 保存内容 |
| --- | --- |
| `snapshots/` | 固定代码起点的完整快照及文件摘要清单 |
| `cases/` | 题目、步骤、案例版本、验收声明、参考修复和案例专用验收资产 |
| `verifiers/` | 多题共用的独立验收脚本、业务测试和数据库夹具 |
| `suites/` | 正式任务集及经过整理的关注任务集，只引用既有案例 |
| `profiles/` | 无密钥、无机器路径的执行条件配置 |
| `assets/` | 多题复用的输入材料 |
| `qualification/` | 起点、参考修复及反例的预期验收结果 |
| `prepare-snapshot.ps1`、`validate-phase3.ps1` | 快照准备与案例资格验证入口 |

案例包内的业务验收测试是“考题的判卷材料”，随案例包提交。评测模块自身的单元测试、测试服务和测试配置仍仅保存在本地独立测试分支；测试提交不合入功能分支或 `dev`。

## 版本与冻结

1. 固定代码起点变更时创建新快照，保留原快照和摘要。当前使用完整快照，不引入下载平台或增量补丁存储。
2. 题面、步骤、验收规则或其他影响题意的内容变更时创建新案例版本；正式任务选择变更时创建新 suite 版本。参考修复用于证明验收可通过，不提供给被测 Agent。
3. 新增或修改案例后，使用 `inspect` 检查声明，使用 `prepare`、`verify` 和案例包资格验证入口检查起点、正确参考及必要反例，再纳入正式任务集。模块测试通过不能代替案例资格验证。
4. 冻结实验时保存 Git 提交、整个案例包摘要、被测 Agent JAR 摘要和实际运行条件。案例包任何文件变动都可能改变整包摘要；同一前后对比必须在同一冻结包上重新建立基线。
5. 已保存的批次和报告保留原身份与结论，不回写为新包版本。新增一次审核或分析不等于新增一次 Agent 执行。

`evaluation/.gitattributes` 为一般文本规定 LF 检出格式。`snapshots/.gitattributes` 对快照源码使用 `-text`，原始行尾也属于摘要的一部分，不能批量格式化快照。已有工作树可能保留旧行尾，验证冻结材料时以干净检出的文件和实际包摘要为准，不能只凭 Git 提交相同就假定本地字节相同。

## 正式关注集与探索性关注集

`suites/regression-focus-v1/` 是已整理的正式关注资产，包含分组 suite 和 `conditions.json`。关注集复用案例，不复制源码和验收代码。

`focus` 命令会在传入的案例包下创建 `suites/<name>/`，因此会改变包摘要。探索时先把完整案例包复制到本地输出目录，再对副本运行 `focus`；确认值得长期保留后，将生成的 suite 和条件说明整理回正式案例包。正式实验必须先完成关注集整理，再冻结包并运行基线和候选版本。不要在已经用于对比的冻结包中途追加文件。

`conditions.json` 是条件来源说明，不是完整运行配置。模型连接、密钥和本机验收工具路径由运行时提供。

## 本地材料

工作空间、模型输入输出、批次、验收日志、报告、问题卡和实验输入不提交到案例包。临时输出可放在已经忽略的 `backend/target/evaluation/`，需要保留的完整归档放在本地 `docs/scratch/evaluation-regression/` 或仓库外；清理 `target` 前先归档。搬迁报告时保留整个目录及相对证据链接。

API key 使用运行时环境变量 `CODEAGENT_EVAL_API_KEY`；包含连接信息或机器路径的 JSON 放在本地输出目录。不要把真实凭据、绝对工具路径或运行结果写入 `profiles/`。其他开发者只需依照根 README 配置自己的环境。

## Git 交付

执行器、案例包和可独立使用的 README 在功能分支分批提交，生产代码只单向合入本地测试分支进行验证。验证通过后将功能分支合入 `dev`，保留有溯源价值的功能分支；测试提交、设计稿和本地运行材料不合入 `dev`。不自动 push。

工具合并只表示评测与报告能力已交付。真实策略变化、同条件基线与候选复测、关注集及全量回归，仍需要各自的执行证据，不能以工具测试或同次执行报告代替。
